# コマを分割する

マンガの原稿を放り込むと、コマを自動で見つけて1コマずつのPNG/JPEGに切り出すブラウザアプリ。
`index.html` をブラウザで開くだけで動く。画像はどこにも送らず、ブラウザの中だけで処理する。

## 対応形式

| 形式 | 備考 |
|---|---|
| PSD / PSB | 「見たまま」の合成画像を読む（レイヤーは読まないので速い）。**CMYKは非対応** |
| TIFF | モノクロ2値・グレースケール・カラー。LZW / ZIP / G4 / 無圧縮 |
| PNG / JPEG | そのまま |

600dpi B4（4842×6874）で1ページ1秒以内に読み込み＋検出が終わる。

## つかいかた

1. 原稿をドロップ（複数ページまとめてOK。ファイル名順に並ぶ）
2. 読み込んだ時点で自動検出が走る
3. ズレているところだけ手で直す
   - 何もない所をドラッグ＝四角いコマを足す／コマの中をドラッグ＝移動（`shift`で水平か垂直だけ）
   - **辺をドラッグ＝その辺だけ平行に動かす**（縦横に伸び縮み。となりの辺は向きを保つので台形にならない）
   - **○をドラッグ＝その角だけ動かす**（斜めにしたいとき）
   - 「水平・垂直にスナップ」がオンだと、角を動かしたとき、辺が**水平・垂直**か**ページ内のほかの辺と同じ角度**になる所に吸い付く
     （右のコマを斜めにしたら、左のコマの辺も同じ角度にそろえられる）。「線で割る」の線も水平・垂直から5°以内ならぴったりになる
   - **「線で割る」＝コマを横切る線を引くと、その線で2つに割れる**（斜めもOK）
   - 辺をダブルクリックで角を1つ増やす、`option`＋○でその角を消す
   - `delete` で消す、`⌘Z` で戻る、`↑` `↓` でページ移動
4. 「まとめて書き出し（ZIP）」→ 元の解像度のまま切り出したZIPが落ちてくる

右の「このページのコマ」の「大きさ」で、切り出したコマの見本を大きくして確かめられる（列の幅も広がる）。

### コマをつなげて1枚で書き出す（セリフがコマをまたぐとき）

右の列の **⛓** で次のコマとつなげる（「全部つなげる」でページ丸ごと。「外す」で戻す）。
つないだコマは1枚で書き出され、名前は `ページ名_01-03.png` のようにコマ番号の範囲になる。

そのとき**コマの外の白（溝・余白）だけ**を「コマ外の塗り」の色で塗る。**溝をまたいでいるフキダシの中の白は残す。**

- コマの中は触らない
- コマの外で、画像の端からたどれる白だけを塗る（バケツ塗り）。フキダシの中の白は輪郭線で閉じているので届かない
- 網点トーンのすき間から漏れないよう、暗い画素を少し太らせて「壁」にしてからたどり、最後に線のきわまで広げる（線は越えない）
- 原寸（600dpi）で1ページ5秒ほど

### 切る位置（枠線の内側／中央／外側）

書き出しの設定の「切る位置」で、枠線のどこで切り抜くかを選ぶ（初期値は内側＝線を含めない）。
画面ではピンクの点線が実際に切る位置。

辺ごとに、辺から内側へたどって枠線の「始まり」と「太さ」を測り、その分だけ辺を平行に動かす。
**書き出すときは原寸で測り直す**（600dpiだと枠線は6〜20pxあるが、プレビューでは1〜5pxしかないため）。
枠線の無い辺（断ち切り・枠の無い絵）は動かさない。24か所測って、半分以上で同じ位置に線が見つかったときだけ枠線とみなす。

ファイル名は `ページ名_01.png` `ページ名_02.png` …。番号は読み順（初期設定は右→左のマンガ読み）。
「全ページ通し番号にする」を入れると、ページをまたいで `_001` から連番になる。

## 自動検出のしくみと、効かないケース

ページを再帰的に切っていく。切れ目の候補は3種類：

| 種類 | 条件 |
|---|---|
| 白い溝 | 大部分が白い帯で、**両脇に枠線（暗い直線）**がある。幅は短辺の0.6%〜4%。フキダシや人物がまたいでいてもよい（「はみ出し許容」） |
| 二重線 | 濃い枠線2本の間にごく細い白（溝が細すぎて白い帯にならないもの）。斜めOK |
| 枠線1本 | 白い溝が無く、枠線だけで区切られた段。縦横のみ（斜めの1本線は絵の線と区別できない） |

斜めは、1/4縮小で「黒い直線がいちばん濃く出る角度」に当たりをつけ、その周りを0.05°刻みで詰める。
長い辺では0.25°ずれるだけで細い二重線がぼやけて消えるため。斜めを探すのはページの12%以上ある大きな領域だけ。

仕上げに、大きな四角いコマの**角に2本の枠線で囲まれたコマ**が収まっていれば切り出す
（5ページ左下のように、L字に囲まれたコマは一刀両断では分けられないため）。

**きれいな切れ目（真っ白な溝・枠線・二重線）を、フキダシや人物・トーンがまたいでいる溝より必ず先に選ぶ。**
またいでいる溝を先に選ぶと、明るいトーンのコマの中を突っ切ってしまう（7ページ）。
先に確かな切れ目で段を分けておけば、その段の中だけで見ることになり、突き抜けない。
これで、下の段の溝の延長で大ゴマを割ってしまう外れ（9・10ページ）も同時に消えた。

切った順がそのまま読み順になる（横に切ったら上が先、縦に切ったら右が先）。
最後に、各コマの辺を中身にぴったり寄せ直す（溝の白い余白を落とす）。
そのとき角に生まれる数pxの小さな面取りはつぶし、ほぼ水平・垂直（1.5°以内）の辺はぴったりそろえる
（四角いコマが5角形になると、角をつかんだときに台形になってしまうため）。

### 実原稿（600dpi・断ち切り多め・16ページ）での結果

- 3ページ（斜めの二重線）、5ページ左下（L字に囲まれたコマ）、7ページ右上（枠の無い絵の隣の枠付きコマ）は取れる
- 2・11ページは、コマ枠をまたぐ人物・フキダシが多く、まだ取れない

よくある外れ方と直し方：

| 外れ方 | 原因 | 直し方 |
|---|---|---|
| 窓の桟・黒フキダシの縁で割れる | 「白い帯＋両脇の黒い線」が溝と同じ形 | 片方を消して、残りを○ドラッグで広げる |
| 隣のコマとくっつく | 人物やフキダシが枠をまたいで、溝も枠線も途切れている | 「線で割る」 |
| 差し込みコマ（コマの中のコマ） | 四角い切れ目では分けられない | 「線で割る」＋角の編集 |

「白とみなす明るさ」「溝の最小幅」「はみ出し許容」「コマの最小サイズ」を動かすと、
表示中のページだけその場で再検出する。全ページに反映したいときは「全ページ自動検出」を押す。

| 症状 | 触るところ |
|---|---|
| コマがくっつく | 「はみ出し許容」を上げる |
| 細かく割れすぎる | 「はみ出し許容」を下げる／「コマの最小サイズ」を上げる／「枠線1本でも切る」を切る |
| 斜めを拾いすぎる | 「斜めコマも探す」を切る |
| 枠線がギリギリで切れる | 「枠を広げる」に数px入れる（原寸のpx） |

斜めコマを書き出すと、コマの外側は「コマ外の塗り」の色で埋まる（初期値は黒）。PNGなら透明にもできる。

## GitHub Pagesで公開する

`index.html` と `lib/` を、リポジトリの**ルート**に置いて Pages を有効にするだけ。
外部CDNを一切使っていないので、これだけで動く。

```
リポジトリ/
├── index.html
└── lib/
    ├── ag-psd.js   PSD読み込み
    ├── UTIF.js     TIFF読み込み
    └── pako.js     TIFFのZIP圧縮の展開に使う
```

Settings → Pages → Source: `Deploy from a branch` → `main` / `/ (root)`。

**⚠️ `テスト原稿/` は未発表の原稿なので、絶対にリポジトリに入れない**（`.gitignore` 済み）。

## メモ

- コマは0〜1の相対座標の多角形で持っている。画面上はプレビュー（長辺1500px）で操作して、
  書き出しのときだけ元ファイルを読み直してフル解像度で切る。何十ページ開いてもメモリが膨らまない。
- ZIPは無圧縮（store）で自前で組み立てている。PNG/JPEGは既に圧縮済みなので、これで困らない。
- CMYKのPSDは ag-psd が読めない。グレースケール／RGBで保存し直すか、TIFFで書き出したものを使う。
- 保存は、ふつうのブラウザ（GitHub Pages・ローカル）では `<a download>`。Artifactとして公開したときだけ
  `claude.use("downloads")` を通す（Artifactのビューアは素のダウンロードを通さないため）。判定は自動。
