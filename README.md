# コマを分割する

マンガの原稿を放り込むと、コマを自動で見つけて1コマずつのPNG/JPEGに切り出すブラウザアプリ。
`index.html` をブラウザで開くだけで動く。画像はどこにも送らず、ブラウザの中だけで処理する。

## 対応形式

| 形式 | 備考 |
|---|---|
| PSD / PSB | 「見たまま」の合成画像を読む（レイヤーは読まないので速い）。**CMYKは非対応** |
| TIFF | モノクロ2値・グレースケール・カラー。LZW / ZIP / G4 / 無圧縮 |
| PNG / JPEG | そのまま |

600dpi B4（4842×6874）で1ページ1秒以内に読み込み＋検出が終わる。

## つかいかた

1. 原稿をドロップ（複数ページまとめてOK。ファイル名順に並ぶ）
2. 読み込んだ時点で自動検出が走る
3. ズレているところだけ手で直す
   - 何もない所をドラッグ＝四角いコマを足す／コマの中をドラッグ＝移動（`shift`で水平か垂直だけ）
   - **辺をドラッグ＝その辺だけ平行に動かす**（縦横に伸び縮み。となりの辺は向きを保つので台形にならない）
   - **○をドラッグ＝その角だけ動かす**（斜めにしたいとき）
   - 「水平・垂直にスナップ」がオンだと、角を動かしたとき、辺が**水平・垂直**か**ページ内のほかの辺と同じ角度**になる所に吸い付く
     （右のコマを斜めにしたら、左のコマの辺も同じ角度にそろえられる）。「線で割る」の線も水平・垂直から5°以内ならぴったりになる
   - **「線で割る」＝コマを横切る線を引くと、その線で2つに割れる**（斜めもOK）
   - 辺をダブルクリックで角を1つ増やす、`option`＋○でその角を消す
   - `delete` で消す、`⌘Z` で戻る、`↑` `↓` でページ移動
4. 「まとめて書き出し（ZIP）」→ 元の解像度のまま切り出したZIPが落ちてくる

右の「このページのコマ」の「大きさ」で、切り出したコマの見本を大きくして確かめられる（列の幅も広がる）。

### 枠外を塗る（セリフがまたいで分けられないコマ）

1つのコマの中に枠付きの絵が複数あって、セリフがまたいでいるため分けられないときに使う。
右の列のそのコマの **「枠外」** をオンにすると、そのコマの中の**枠線の外の白（余白・溝）だけ**を「コマ外の塗り」の色で塗る。
枠の中の白、フキダシやキャプションの中の白、余白にはみ出した花びらなど輪郭で閉じた白は残る。

- 切り抜く範囲の**少し外側**から白をたどる。切り抜く位置が枠線のすぐ内側でも、絵の中へ漏れないようにするため
- **そのコマの中で自動検出をもう一度走らせ、中にあるコマを「守る所」にする**。
  守った所の中へは、端からの塗りは入らない。断ち切りのコマ（絵がページの端まで届いている）でも、
  ページの端から絵の白（柱のハイライトや背景）へ入り込まない。
  2ページをページ丸ごと1コマにして「枠外」を押すだけで、左上の余白と斜めの溝が塗られ、溝をまたぐフキダシは残る
- 守る所の辺は、枠線の外側のふちから1.5pxだけ線の中に入れる（検出した辺のままだと枠線より数px外にあり、
  溝の黒と枠線のあいだに細い白い線が残った）。2ページで、バケツで塗った結果と画素単位で一致することを確認
- 中のコマが見つからないときは、ページの外を壁にして、そこからはたどらない（断ち切りの絵へ漏れないように）
- 初回は中のコマを探すので数秒かかる
- 塗った結果は編集画面にそのまま重ねて表示される

**溝が閉じていて塗り残ったとき**は **「バケツ」** でその白をクリックすると塗られる（`option`＋クリックで取り消し）。
例：4ページ2コマ目の、2つの枠のあいだの溝。上の端に網点トーンがかかり、下はキャプションの箱で閉じているので、外からはたどれない。
形だけで「溝」と決めつけると絵の中の窓ガラスなども塗ってしまうので、ここは手で指定する。

### コマの重なり

**番号の若いコマが優先。あとのコマは、先のコマと重なっている所が「コマ外の塗り」で塗られる**（同じ絵が2回出ることはないので）。
「枠外」のオン・オフに関係なく常にそうなる。大きな四角で囲ったコマの中に、先の番号のコマ（斜めのコマなど）が
食い込んでいるとき（8ページの2コマ目）に効く。

- 編集画面では、あとのコマの黒を先のコマの上にかぶせない（先のコマの絵が隠れて作業しにくいので）。右の列の見本と書き出しでは黒くなる
- 境目で数pxだけ重なるのはよくある（幅はページいっぱいでも厚みは3pxほど）ので、重なりの厚み（面積÷長い辺）が
  プレビューで10px（原寸で約40px）未満なら無視する。最初は面積で判定していて、自動検出の16ページ中7ページで
  境目の細い重なりを拾ってしまった

### 白フチ

黒く塗ったまわりでフキダシの輪郭が分からなくなるときは **「白フチ」** でフキダシの中をクリックする。
クリックした所からフキダシの形をたどり（中の文字の穴は埋める）、そのまわりの帯のうち**塗った所だけを削って元の絵（白い紙）に戻す**。
「黒く塗った所の一部を、輪郭線に沿って削る」という考え方。枠線や絵の黒は塗ったものではないので削らない。
黒いフキダシ（中が黒）は、黒い所をクリックすればよい。
（最初の版は白い帯を上から描いていて、枠線や絵の上にも白が乗り、使い方が分かりにくかった）

フキダシの「形」は、クリックした中の白から、**黒い輪郭線を最後までたどった外側まで**。削る帯はそこからさらに外側。
（一時、中の白から一律に3px広げたものを形にしていて、帯のほとんどが輪郭線の上に乗り、塗った黒まで届かず削れなかった）
漏れの判定は「形が全体の60%を超える」か「3辺以上に接する」。1つの黒いフキダシを囲んだコマでも通るように
帯の太さは、白フチのボタンの横の「太さ」（プレビューのpx。原寸では約4倍）。

**はみ出した花びらなど**も同じ道具で付けられる。クリックした所が「塗った黒の中に島のように残った、塗られていない所」なら、
その島の輪郭に沿って削る（中が白でもトーンでもよい）。島でなければ（コマの中までつながったフキダシなど）、中をたどって形を取る。
枠線に触れてはみ出しているものは、枠線を通じてコマの絵全体とつながってしまうので、
そのコマの中で見つけたコマの**枠線まわり6px**と**ページの外**を壁にして、その外側だけで島を見る。
中のコマ探しは「枠外」のオン・オフに関係なく、白フチがあるときに行う（バケツで塗ったコマでも、枠線に触れた花びらに付くように）。

島として取れないもの（中のコマ探しで2つの枠が1つにつながって見つかり、その中に入ってしまった花びらなど）は、
クリックした所から中をたどって形を取る。そのとき**切り抜く範囲の外は壁**にし（コマの辺にまたがった花びらが、
外の白とつながらないように）、帯が塗った所にかからなければ**トーンも通れるようにして**たどり直す（中にトーンが貼られた花びら）。

### 白フチブラシ（おすすめ）

形を自動で探すやり方は、閉じていない物（ページの端で切れた花びら、枠線と重なった花びら、はみ出した頭）で
どこまでが形か決められず、うまくいかない。そこで **「白フチブラシ」** で、はみ出した物の輪郭のあたりをなぞる。

- なぞった範囲の中で、**塗った所のうち、元の絵の線から「太さ」以内だけ**を元に戻す（＝輪郭に沿って削る）
- 形を探さないので、切れた花びらも大きな頭も同じ
- **長い縦・横の直線（枠線）と、小さな点（網点トーン）は「線」として扱わない**。
  細い溝の中をなぞっても、枠線やトーンの点のまわりは削れない
- 大きさは消しゴムと共通

**「はみ出しに白フチ」**：選んでいるコマの島を全部見つけて、まとめて白フチの点を置く。
30画素未満の小さなもの（トーンの点など）は除外。いらないものは白フチの道具で `option`＋クリック。
（最初は「閉じた白」を探していたが、トーンの点のあいだのすき間を拾い、トーンの貼られた花びらは見つけられなかった）
輪郭のすき間から外へ漏れて形が見つからないときは、点が赤くなり、その白フチは付かない。

それでも思いどおりにならない所は手で直す：

- **「四角で塗る」**：ドラッグした四角をそのまま塗る。トーンがかかっていてバケツが効かない所に
- **「消しゴム」**：なぞった所は塗らない（元の絵に戻す）。横の丸で大きさを変える。四角で塗った所も消せる

バケツと四角で塗るは、1回使ったら自動で「選ぶ・動かす」に戻る。消しゴムは何度もなぞれるようオンのまま
（画面の上に「消しゴム中」と出る。Escかもう一度ボタンで戻る）。どの道具がオンでも、選んだコマの角と辺は動かせる。

薄い輪郭（花びらなど）の中へ漏れないよう、白をたどるときは「少しでも色がある画素」を壁にしている
（最初は暗い画素だけを壁にしていて、縮小した表示で花びらの細い輪郭がすり抜けていた）。

### コマをつなげて1枚で書き出す（セリフがコマをまたぐとき）

右の列の **⛓** で次のコマとつなげる（「全部つなげる」でページ丸ごと。「外す」で戻す）。
つないだコマは1枚で書き出され、名前は `ページ名_01-03.png` のようにコマ番号の範囲になる。

そのとき**コマの外の白（溝・余白）だけ**を「コマ外の塗り」の色で塗る。**溝をまたいでいるフキダシの中の白は残す。**

- コマの中は触らない
- コマの外で、画像の端からたどれる白だけを塗る（バケツ塗り）。フキダシの中の白は輪郭線で閉じているので届かない
- 網点トーンのすき間から漏れないよう、暗い画素を少し太らせて「壁」にしてからたどり、最後に線のきわまで広げる（線は越えない）
- 原寸（600dpi）で1ページ5秒ほど

### 切る位置（枠線の内側／中央／外側）

書き出しの設定の「切る位置」で、枠線のどこで切り抜くかを選ぶ（初期値は内側＝線を含めない）。
画面ではピンクの点線が実際に切る位置。

辺ごとに、辺から内側へたどって枠線の「始まり」と「太さ」を測り、その分だけ辺を平行に動かす。
**書き出すときは原寸で測り直す**（600dpiだと枠線は6〜20pxあるが、プレビューでは1〜5pxしかないため）。
枠線の無い辺（断ち切り・枠の無い絵）は動かさない。24か所測って、半分以上で同じ位置に線が見つかったときだけ枠線とみなす。

ファイル名は `ページ名_01.png` `ページ名_02.png` …。番号は読み順（初期設定は右→左のマンガ読み）。
「全ページ通し番号にする」を入れると、ページをまたいで `_001` から連番になる。

## 自動検出のしくみと、効かないケース

ページを再帰的に切っていく。切れ目の候補は3種類：

| 種類 | 条件 |
|---|---|
| 白い溝 | 大部分が白い帯で、**両脇に枠線（暗い直線）**がある。幅は短辺の0.6%〜4%。フキダシや人物がまたいでいてもよい（「はみ出し許容」） |
| 二重線 | 濃い枠線2本の間にごく細い白（溝が細すぎて白い帯にならないもの）。斜めOK |
| 枠線1本 | 白い溝が無く、枠線だけで区切られた段。縦横のみ（斜めの1本線は絵の線と区別できない） |

斜めは、1/4縮小で「黒い直線がいちばん濃く出る角度」に当たりをつけ、その周りを0.05°刻みで詰める。
長い辺では0.25°ずれるだけで細い二重線がぼやけて消えるため。斜めを探すのはページの12%以上ある大きな領域だけ。

仕上げに、大きな四角いコマの**角に2本の枠線で囲まれたコマ**が収まっていれば切り出す
（5ページ左下のように、L字に囲まれたコマは一刀両断では分けられないため）。

**きれいな切れ目（真っ白な溝・枠線・二重線）を、フキダシや人物・トーンがまたいでいる溝より必ず先に選ぶ。**
またいでいる溝を先に選ぶと、明るいトーンのコマの中を突っ切ってしまう（7ページ）。
先に確かな切れ目で段を分けておけば、その段の中だけで見ることになり、突き抜けない。
これで、下の段の溝の延長で大ゴマを割ってしまう外れ（9・10ページ）も同時に消えた。

切った順がそのまま読み順になる（横に切ったら上が先、縦に切ったら右が先）。
最後に、各コマの辺を中身にぴったり寄せ直す（溝の白い余白を落とす）。
そのとき角に生まれる数pxの小さな面取りはつぶし、ほぼ水平・垂直（1.5°以内）の辺はぴったりそろえる
（四角いコマが5角形になると、角をつかんだときに台形になってしまうため）。

### 実原稿（600dpi・断ち切り多め・16ページ）での結果

- 3ページ（斜めの二重線）、5ページ左下（L字に囲まれたコマ）、7ページ右上（枠の無い絵の隣の枠付きコマ）は取れる
- 2・11ページは、コマ枠をまたぐ人物・フキダシが多く、まだ取れない

よくある外れ方と直し方：

| 外れ方 | 原因 | 直し方 |
|---|---|---|
| 窓の桟・黒フキダシの縁で割れる | 「白い帯＋両脇の黒い線」が溝と同じ形 | 片方を消して、残りを○ドラッグで広げる |
| 隣のコマとくっつく | 人物やフキダシが枠をまたいで、溝も枠線も途切れている | 「線で割る」 |
| 差し込みコマ（コマの中のコマ） | 四角い切れ目では分けられない | 「線で割る」＋角の編集 |

「白とみなす明るさ」「溝の最小幅」「はみ出し許容」「コマの最小サイズ」を動かすと、
表示中のページだけその場で再検出する。全ページに反映したいときは「全ページ自動検出」を押す。

| 症状 | 触るところ |
|---|---|
| コマがくっつく | 「はみ出し許容」を上げる |
| 細かく割れすぎる | 「はみ出し許容」を下げる／「コマの最小サイズ」を上げる／「枠線1本でも切る」を切る |
| 斜めを拾いすぎる | 「斜めコマも探す」を切る |
| 枠線がギリギリで切れる | 「枠を広げる」に数px入れる（原寸のpx） |

斜めコマを書き出すと、コマの外側は「コマ外の塗り」の色で埋まる（初期値は黒）。PNGなら透明にもできる。

## GitHub Pagesで公開する

`index.html` と `lib/` を、リポジトリの**ルート**に置いて Pages を有効にするだけ。
外部CDNを一切使っていないので、これだけで動く。

```
リポジトリ/
├── index.html
└── lib/
    ├── ag-psd.js   PSD読み込み
    ├── UTIF.js     TIFF読み込み
    └── pako.js     TIFFのZIP圧縮の展開に使う
```

Settings → Pages → Source: `Deploy from a branch` → `main` / `/ (root)`。

**⚠️ `テスト原稿/` は未発表の原稿なので、絶対にリポジトリに入れない**（`.gitignore` 済み）。

## メモ

- コマは0〜1の相対座標の多角形で持っている。画面上はプレビュー（長辺1500px）で操作して、
  書き出しのときだけ元ファイルを読み直してフル解像度で切る。何十ページ開いてもメモリが膨らまない。
- ZIPは無圧縮（store）で自前で組み立てている。PNG/JPEGは既に圧縮済みなので、これで困らない。
- CMYKのPSDは ag-psd が読めない。グレースケール／RGBで保存し直すか、TIFFで書き出したものを使う。
- 保存は、ふつうのブラウザ（GitHub Pages・ローカル）では `<a download>`。Artifactとして公開したときだけ
  `claude.use("downloads")` を通す（Artifactのビューアは素のダウンロードを通さないため）。判定は自動。
